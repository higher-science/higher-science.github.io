# 如何发帖（higher-science.github.io）

> 一句话：把稿子给 `tools/new_post.py`，加 `--push`，约 1 分钟后线站自动更新。
> 不需要打开 GitHub 网页，不需要手动拖文件。

---

## 一、三种用法

### 1. 有草稿文件（最常用）

```bash
python tools/new_post.py \
  --title "为什么知识越多越危险" \
  --file "F:\HighScience-KB\09_宣传材料\草稿.md" \
  --slug wei-shen-me-zhi-shi-yue-duo-yue-wei-xian \
  --categories 认知,教育 \
  --tags 信息茧房,认知权 \
  --push
```

### 2. 正文直接写在命令里（短评、按语）

```bash
python tools/new_post.py --title "短评：从组成走向生成" --body "正文……" --push
```

### 3. 先看会生成什么，不发布

```bash
python tools/new_post.py --title "测试" --body "x" --dry
```

---

## 二、参数速查

| 参数 | 必填 | 说明 |
|---|---|---|
| `--title` | 是 | 文章标题 |
| `--file` / `--body` | 二选一 | 正文来源（UTF-8 的 .md 或 .txt） |
| `--slug` | 否 | 网址用的英文短名。**不填就用标题原文，网址会是一串中文**（能开，但不好分享）。建议填 |
| `--date` | 否 | 发布日 `YYYY-MM-DD`，默认今天 |
| `--categories` | 否 | 分类，逗号分隔，如 `科学,教育` |
| `--tags` | 否 | 标签，逗号分隔 |
| `--desc` | 否 | 摘要（用于列表页与搜索引擎），默认取正文前 80 字 |
| `--image` | 否 | 封面图，放 `assets/` 下后写 `/assets/xxx.png` |
| `--pin` | 否 | 置顶：`--pin true`，或 `--pin 1`（数字越小越靠前） |
| `--push` | 否 | 生成后自动提交并推送，触发线上构建 |
| `--dry` | 否 | 只预览，不写文件 |

---

## 三、上线之后

- 线上地址：`https://higher-science.github.io/posts/<slug>/`
- 构建进度：`https://github.com/higher-science/higher-science.github.io/actions`
  （看到 `Build and Deploy` 变绿就上线了；一般 40–90 秒）

## 四、出问题时

| 现象 | 原因 | 处理 |
|---|---|---|
| `推送失败` + `CONNECT tunnel failed` | 代理没开或端口变了 | 打开 Clash 后重试同一命令（加 `--push`）。文件已存在本地，不会白写 |
| `已存在同名文件，未覆盖` | 当天同名文章已发过 | 换一个 `--slug`，或先改掉旧文件 |
| 想改已经发出去的文章 | —— | 直接编辑 `_posts/` 下那个 `.md`，然后 `git add -A && git commit -m "edit" && git push` |
| 想撤下一篇 | —— | 删掉 `_posts/` 下的文件，commit + push，线上随之消失 |

---

## 五、这个工具放在 `tools/` 里的原因

`_config.yml` 的 `exclude` 列表里排除了 `tools` 与 `README.md`，
所以这个脚本**不会**被构建成网页，也不会出现在线站上。
你可以放心往 `tools/` 里放自己的草稿、模板、索引脚本。
