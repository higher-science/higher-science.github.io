# 如何发帖（higher-science.github.io）

> 一句话：把稿子给 `tools/new_post.py`，加 `--push`，约 1 分钟后线站自动更新。
> 不需要打开 GitHub 网页，不需要手动拖文件。

---

## 一、三种用法

### 1. 有草稿文件（最常用）

```bash
python tools/new_post.py \
  --title "为什么知识越多越危险" \
  --file "F:\HighScience-KB\09_宣传材料\草稿.md" \
  --slug wei-shen-me-zhi-shi-yue-duo-yue-wei-xian \
  --categories 认知,教育 \
  --tags 信息茧房,认知权 \
  --push
```

### 2. 正文直接写在命令里（短评、按语）

```bash
python tools/new_post.py --title "短评：从组成走向生成" --body "正文……" --push
```

### 3. 先看会生成什么，不发布

```bash
python tools/new_post.py --title "测试" --body "x" --dry
```

---

## 二、参数速查

| 参数 | 必填 | 说明 |
|---|---|---|
| `--title` | 是 | 文章标题 |
| `--file` / `--body` | 二选一 | 正文来源（UTF-8 的 .md 或 .txt） |
| `--slug` | 否 | 网址用的英文短名。**不填就用标题原文，网址会是一串中文**（能开，但不好分享）。建议填 |
| `--date` | 否 | 发布日 `YYYY-MM-DD`，默认今天 |
| `--categories` | 否 | 分类，逗号分隔，如 `科学,教育` |
| `--tags` | 否 | 标签，逗号分隔 |
| `--desc` | 否 | 摘要（用于列表页与搜索引擎），默认取正文前 80 字 |
| `--image` | 否 | 封面图，放 `assets/` 下后写 `/assets/xxx.png` |
| `--pin` | 否 | 置顶：`--pin true`，或 `--pin 1`（数字越小越靠前） |
| `--push` | 否 | 生成后自动提交并推送，触发线上构建 |
| `--dry` | 否 | 只预览，不写文件 |

## 三、上线之后

- 线上地址：`https://higher-science.github.io/posts/<slug>/`
- 构建进度：`https://github.com/higher-science/higher-science.github.io/actions`

## 四、出问题时

推送这一步会自动按 **直连 → GitHub 备用 IP → 本机代理** 的顺序试，所以大多数网络问题不用管。
工具还会**主动清掉环境里的 `HTTP_PROXY` / `HTTPS_PROXY`**——本机环境变量里的那个代理会把 git 带沟里
（报 `502 Bad Gateway` 或 `10054 连接被重置`），不清掉必失败。

| 现象 | 原因 | 处理 |
|---|---|---|
| `推送失败` 且提示所有通道都不通 | 网络整体不通 | 检查网络后重试同一命令。**文件已保存到本地，不会白写**，再跑一次 `--push` 即可 |
| `Could not resolve host: github.com` | DNS 异常 | 见下节「网不通时的手动兜底」 |
| `已存在同名文件，未覆盖` | 当天同名文章已发过 | 换一个 `--slug`，或先改掉旧文件 |
| `Updates were rejected` | 远端有你本地没有的提交 | 先 `git pull --rebase origin main`，再重试 |
| 想改已经发出去的文章 | —— | 直接编辑 `_posts/` 下那个 `.md`，然后 commit + push |
| 想撤下一篇 | —— | 删掉 `_posts/` 下的文件，commit + push，线上随之消失 |

### 网不通时的手动兜底

截至 2026-09-19 实测：本机 `github.com` 由 DNS 解析到的那个 IP（20.205.243.166）**不通**，
但 GitHub 的备用 IP **通**。工具会自动试，若你想手动指定：

```bash
git -c http.proxy= -c http.curloptResolve=github.com:443:140.82.114.3 push origin main
```

（`-c http.proxy=` 是**显式关掉代理**，这一步不能省。备用 IP 依次为
`140.82.114.3` → `140.82.113.3` → `140.82.112.3` → `140.82.121.3`。）

想一条命令永久生效，可在仓库里设一次：

```bash
git config --local http.proxy ""
git config --local http.curloptResolve github.com:443:140.82.114.3
```

**注意**：IP 会变。若哪天又推不上去，先跑一次通路体检（见下），它会告诉你当前哪条路通。

### 通路体检

```bash
cd C:\Users\R\WorkBuddy\高等科学体系创建
python _zenodo_path\path_check.py
```

一次把「发帖通路 / GitHub→Zenodo 挂钩 / 许可证识别 / 元数据 / DOI 状态」全查一遍，
只读、不改任何东西。也支持 `--quiet`（只在有问题时输出）与 `--json`。

## 五、这个工具放在 `tools/` 里的原因

`_config.yml` 的 `exclude` 列表里排除了 `tools` 与 `README.md`，
所以这个脚本**不会**被构建成网页，也不会出现在线站上。
你可以放心往 `tools/` 里放自己的草稿、模板、索引脚本。
